    Write the human sentence once and reuse it: "Elevated errors in EU-West", "Planned maintenance", "Third-party outage". A template pre-fills the timeline stages and the subscriber email; you edit the specifics. Templates are per page, so a private on-call page can be blunter than the public one.

    Heartbeat monitors

    For the things that call you: cron jobs, queue workers, nightly backups. Each gets a URL; if the ping does not arrive inside the window the monitor goes amber, then rose. Grace periods are per monitor.

Incidents on the record

Relay's own status page is run by someone else; the write-ups are Relay's. Open one.

22 August: subscriber emails delayed 40 minutes

A queue worker in the notification service restarted with an old config and pointed at a retired mail relay. Checks passed because the relay accepted connections; it never delivered. The mail path is now heartbeated end to end, with a mailbox that expects a message every five minutes.

×

Impact: 1,240 incident emails delivered late. No status pages were affected.

9 August: false amber on 31 monitors in Sydney

An upstream DNS resolver in Sydney began returning SERVFAIL for a fraction of lookups. One region cannot open an incident, so nothing went rose, but customers saw Sydney listed as failing for 22 minutes. A second resolver is now tried before a DNS failure is recorded.

!

Impact: cosmetic. No incident opened, no email sent.

27 July: planned maintenance, 15 minutes

Database version upgrade. Announced a week ahead, finished in eleven minutes, checks continued from a read replica throughout. On the record because a maintenance that goes to plan is still worth writing down.

✓

Impact: none. The dashboard was read-only for eleven minutes.
