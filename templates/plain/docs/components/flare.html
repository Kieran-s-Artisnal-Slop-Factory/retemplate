Component

Flare

Flare is everything a template adds beyond the contract: waves, glows, ornaments, textures. Plain adds nothing, so this page explains the convention the other templates follow.

The convention

A template's extra classes are prefixed with its name (.neon-glow, .glassy-waves). When flare needs markup rather than just CSS, it lives inside one wrapper named after the template, so that swapping templates can strip it mechanically:

<div class="plain-flare">
  <!-- A template's decorative markup goes inside a wrapper named after it. -->
</div>

Why it matters

Every template shares the same component markup. Flare is the one place that promise is relaxed, and the prefix is what keeps the relaxation visible: a class that starts with a template's name is not portable, and everything else is.

Classes

The rules live in css/global.css under /* == flare == */.

ClassPurpose
.plain-flarePlain has no flare; the section in global.css is empty

Notes

  • Flare must still use tokens — no colour literals in global.css. A template that needs a new colour adds a --<name>-* token to theme.css.
  • Animations honour prefers-reduced-motion.
